# AI Tutor Screener — Backend

Backend for an AI-powered first-round **tutor screening** system for Cuemath.

A candidate connects to a persistent WebSocket, has a short voice conversation
with an AI interviewer, and the backend produces an **evidence-backed
assessment** across six tutoring soft-skill dimensions. This repository is the
backend only — the frontend is not included.

## Features

- **WebSocket voice interview** (`/ws/interview/{session_id}`) — binary audio in,
  binary audio + typed events out.
- **Local, replaceable providers** behind `Protocol` interfaces:
  - `AIProvider` — `nvidia` (free endpoint, e.g. `openai/gpt-oss-20b`), `openai`,
    `ollama`, or `mock` (offline)
  - `SpeechToText` — `faster-whisper` (local, offline)
  - `TextToSpeech` — `edge-tts` (free, natural voices)
- **Interview state machine** — INTRO → WARMUP → TEACHING → PATIENT → EMPATHY →
  ADAPTIVE → CLOSING → ASSESSMENT, with follow-ups, short-answer probing, silence
  handling, and stage coverage tracking.
- **AI-driven conversation** — the interviewer's questions are generated by the
  AI provider from the conversation context (it listens, adapts, and follows up
  on vague answers), so the flow is natural rather than scripted. The static
  question bank is only a fallback when the AI provider is unavailable. Each
  question is logged with its `source` (`ai` vs a bank id) for verification.
- **Abuse / non-cooperation handling** — if the candidate gives an aggressive,
  abusive, or disengaged answer, the AI politely terminates the interview.
  The session is marked with `fail_reason` and the assessment returns
  `DO_NOT_PROCEED` with a clear explanation. A unit test covers this path.
- **Assessment engine** — scores Clarity, Simplicity, Patience, Warmth, Fluency,
  Adaptability with **mandatory transcript evidence** and a hiring recommendation.
- **HTTP session lifecycle** — create, fetch, complete, fetch assessment.
- Async-first, structured JSON logging, no secrets in code, clean error contracts.

## Quick start

Requires Python 3.11+ and [uv](https://docs.astral.sh/uv/).

```bash
cd backend
uv sync                       # install dependencies
cp .env.example .env          # defaults run offline (mock AI)
uv run uvicorn app.main:app --reload --reload-include '.env' --port 8000
```

> `--reload-include '.env'` makes the server restart automatically whenever you
> edit `.env`, so provider/key changes take effect without manual restarts.

- API docs: http://localhost:8000/docs
- Health: http://localhost:8000/api/v1/health

The default configuration (`AI_PROVIDER=mock`) runs with **no external services**.

### Using NVIDIA (free endpoint)

Get a free API key from [build.nvidia.com](https://build.nvidia.com), then in `.env`:

```dotenv
AI_PROVIDER="nvidia"
AI_MODEL="openai/gpt-oss-20b"
AI_API_KEY="nvapi-..."          # your full key (~66 chars, starts with nvapi-)
AI_BASE_URL="https://integrate.api.nvidia.com/v1"
```

`openai/gpt-oss-20b` is a reasoning model, so keep `AI_TIMEOUT_SECONDS=120` and the
default token budgets — the assessment needs headroom for its hidden reasoning.

> **No valid key? No problem.** The interviewer falls back to a built-in question
> bank whenever the AI provider fails, so speech keeps working with a broken or
> missing key. Only natural follow-ups and the evidence scoring need a real model.

## WebSocket protocol

Connect: `ws://localhost:8000/ws/interview/{session_id}`

**Client → server (text JSON)**

```json
{ "type": "session.start" }
{ "type": "audio.end" }
{ "type": "candidate.text", "data": { "text": "I'd explain fractions..." } }
{ "type": "session.end" }
{ "type": "ping" }
```

Binary frames (`audio.chunk`) carry raw audio while the candidate speaks; send
`audio.end` when the candidate has finished their turn. `candidate.text` is a
testing shortcut that feeds a typed answer straight into the interview engine,
skipping speech-to-text.

**Server → client (text JSON)**

```json
{ "type": "session.ready", "data": { "session_id": "..." } }
{ "type": "interviewer.state", "data": { "state": "speaking|listening|thinking" } }
{ "type": "interviewer.transcript", "data": { "text": "Hello, welcome..." } }
{ "type": "candidate.transcript", "data": { "text": "I'd explain fractions..." } }
{ "type": "interviewer.response", "data": { "text": "...", "stage": "WARMUP" } }
{ "type": "audio.start", "data": { "format": "audio/pcm_s16le", "sample_rate": 24000 } }
{ "type": "silence.prompt", "data": { "message": "..." } }
{ "type": "assessment.started" }
{ "type": "assessment.completed" }
{ "type": "session.completed" }
{ "type": "error", "data": { "code": "TRANSCRIPTION_FAILED", "message": "..." } }
```

Server → client binary frames are **16-bit PCM, mono, 24 kHz** audio chunks of the
interviewer's speech. Each utterance is announced by an `audio.start` event (with
`format` and `sample_rate`) and terminated by an `audio.end` text event. The audio
is already trimmed of trailing silence.

### Playing interviewer audio in the browser

```js
let ctx = null, bufferSource = null;

function audioContext() {
  ctx = ctx || new AudioContext({ sampleRate: 24000 });
  if (ctx.state === "suspended") ctx.resume();
  return ctx;
}

function playPcm(chunks, sampleRate = 24000) {
  const flat = new Uint8Array(chunks.reduce((n, c) => n + c.length, 0));
  let off = 0;
  for (const c of chunks) { flat.set(c, off); off += c.length; }

  const pcm = new Float32Array(flat.length / 2);
  for (let i = 0; i < pcm.length; i++)
    pcm[i] = (flat[i * 2] | (flat[i * 2 + 1] << 8)) / 32768;

  const ctx = audioContext();
  const buf = ctx.createBuffer(1, pcm.length, sampleRate);
  buf.copyToChannel(pcm, 0);

  bufferSource?.stop();
  bufferSource = ctx.createBufferSource();
  bufferSource.buffer = buf;
  bufferSource.connect(ctx.destination);
  bufferSource.start();
}
```

On `audio.start` reset the PCM chunk buffer; append each binary frame; on
`audio.end` call `playPcm(buffer)`. Do **not** create a new `AudioContext` per
utterance (browsers limit this and it triggers "AudioContext encountered an
error"): create it once, reuse it.

### Typical flow

1. `POST /api/v1/sessions` → get `session_id`
2. Connect WebSocket → receive `session.ready`
3. Send `session.start` → interviewer greets (transcript + audio)
4. Candidate speaks → client streams binary audio → sends `audio.end`
5. Server replies with `candidate.transcript`, `interviewer.response`, and audio
6. Send `session.end` → server finalizes, runs assessment, emits
   `assessment.completed`
7. Fetch `GET /api/v1/sessions/{id}/assessment`

## Configuration

All values are environment-driven via Pydantic Settings (see `.env.example`):

- **Interview behaviour**: silence thresholds, short-answer word count, follow-up
  budget, max total questions.
- **AI**: `AI_PROVIDER` (`mock` | `nvidia` | `openai` | `ollama`), `AI_MODEL`, `AI_API_KEY`,
  `AI_BASE_URL`, temperature, timeout, max tokens, max retries.
- **STT**: `STT_PROVIDER` (`local`), `STT_MODEL` (`tiny`/`base`/…), device, compute type.
- **TTS**: `TTS_PROVIDER` (`edge`), `TTS_VOICE`, `TTS_RATE`.
- **CORS**: `CORS_ORIGINS` (comma-separated; no wildcard by default).

## How audio flows

```
Microphone → binary WS frames → audio buffer → audio.end
  → STT (faster-whisper, in a worker thread)
  → InterviewEngine → AIProvider
  → interviewer text → TTS (edge-tts)
  → binary WS frames → browser speaker
```

CPU-heavy STT/TTS/model work runs off the event loop (`asyncio.to_thread`).

## Fairness

Assessment evaluates **tutoring behaviour and communication only**. It never
considers accent, regional origin, gender, ethnicity, appearance, or background.
"Fluency" means comprehensibility, vocabulary, and sentence construction — not
native-speaker status. Scores require direct transcript evidence; without it a
dimension is marked `INSUFFICIENT` rather than hallucinated.
